Merge and variation intelligence

A component brings
more than its source file.

Before adopting code from a declared variation or companion, review its dependency closure and target fit. SAGE's Merge layer assembles static evidence and an actionable review plan; it does not blindly copy code or resolve Git conflicts.

Check Merge evidence and scope
  1. Package the dependency surface.Identify required files, unresolved internal paths and external packages within the declared closure bound.
  2. Inspect integration requirements.Review target conflicts and available provider, router, i18n and browser-API harness needs.
  3. Review the recommendation and its reasons.The cockpit distinguishes Import Now, Import With Review and Do Not Import Yet. Missing compiler or runtime evidence remains missing.
  4. Carry a verification and rollback plan.Generated task packs support human-reviewed adoption; a recommendation is not mutation approval or proven runtime compatibility.
For AI-assisted engineering

Context is useful.
Unbounded authority is not.

SAGE is not another coding agent. It supplies repository context and static evidence to the developer or agent already doing the work.

Read the progressive HITL runbook
  1. Name the target.Keep the repository, selected projects and acquired evidence explicit.
  2. Focus the investigation.Inspect a file or symbol, follow state/dependencies and ask which rules apply.
  3. Review the change context.Use existing impact, test-impact and upstream-trace tools. Missing evidence stays visible.
  4. Verify before action.Static candidates are not executed tests. Follow applicable human approval and native verification requirements.
