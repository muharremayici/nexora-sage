# Nexora SAGE Positioning

## Official Name

**Nexora S.A.G.E.** is the formal brand name.

**Nexora SAGE** is the search-friendly spelling used in README titles, package names, website copy and CLI-facing docs.

S.A.G.E. means **Sovereign Architectural Governance Engine**.

## Category

Nexora SAGE is an AI-native architectural governance engine with a polyglot architecture-governance substrate and deepest analysis depth in TypeScript/React systems.

The long-term category direction is a local-first Sovereign Engineering Kernel: a governance layer that normalizes evidence from repositories, specialist tools and eventually runtime systems. This is a strategic direction, not a claim that v1 is already a complete Repository Digital Twin or runtime governance platform.

It is not positioned as a Biome, ESLint or SonarQube clone. Those tools primarily lint, format, report or dashboard. Nexora SAGE produces evidence-backed architectural decisions, merge readiness, human approval gates and AI-agent consumable artifacts.

## One-Sentence Description

Nexora SAGE helps AI agents and human maintainers understand, govern and transform polyglot application architecture, with its strongest specialization in TypeScript/React, evidence, confidence scoring and human-in-the-loop control.

## Truth Labels

Use these labels in public claims:

- **Proven**: local artifact, validator or command output exists.
- **Partially Proven**: infrastructure exists, but broader fixtures or outside users are still needed.
- **Roadmap**: planned capability, not a current product claim.

- 1.0.0 release evidence supports `evidence_backed_universal_react_web_static_governance` within its declared static/runtime boundary.
- Claim Guard prevents broad React or release claims from exceeding evidence.
- Post-Atlas Architecture Oracle proposes architecture blueprints from observed Atlas topology and keeps human sealing advisory.
- React evidence ladder and runtime proof status exist.
- React Compiler readiness is a first-class artifact.
- RSC, Server Actions, a11y/i18n and state/data graph contracts are reported.
- Merge dependency harness, static simulation, confidence components and AI task proof contracts exist.
- Config, signal baseline and TypeScript runtime provenance are documented and validated.
- MCP/HITL agent surfaces exist as Nexora-oriented interfaces.
- Polyglot discovery, runtime config, source classification, Atlas dispatch, path resolution and MCP patch governance are integrated.
- External Architecture Oracle blueprint calibration has been run against existing target artifacts and locked into regression contracts.

## Current Partially Proven Claims

- Auto-doctrine works, but template diversity is still being expanded.
- External repository analysis and source-checkout onboarding are packaged;
  broader independent-user and repeat-use evidence is still needed.
- Real-repository and holdout testing exists, but public reproducible demos
  still need curation.
- Local Dev Telemetry exists for explicit local traces, but production-grade framework runtime probes are still a roadmap item.
- Runtime omniscience is not the 1.0.0 claim; current release scope is evidence-backed universal React web static governance with explicit runtime-proof boundaries.

## Roadmap Claims

- VS Code extension / LSP.
- Production-grade runtime tracing via Vite/Rollup/browser probe.
- First-class GitHub Action marketplace package beyond the shipped minimal
  source-checkout workflow.
- Optional external sensor bridges for Biome, Knip, Madge/dpdm, SonarQube and CodeScene-style data.
- Provenance-preserving external evidence adapters for CI, security, tests and observability.
- Repository Digital Twin as the composition of Atlas, Doctrine, ContextOS, historical cognition and runtime evidence, not as a standalone v1 feature.

## Competitor Posture

Nexora SAGE does not need to depend on competitor tools to be useful. External tools should be optional sensors or enterprise bridges only:

- Biome: optional lint/format signal.
- Knip: optional dead-code corroboration.
- Madge/dpdm: optional circular dependency cross-check.
- SonarQube: optional enterprise export/bridge.
- CodeScene-style data: optional hotspot/history corroboration.

The core engine remains independent.
